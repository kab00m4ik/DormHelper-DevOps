# ADR-0002: Вибір технологічного стеку та асинхронної обробки задач у Kubernetes

- **Статус:** Прийнято (Accepted)
- **Дата:** 2026-11-25

## Контекст

Проєкт **DormHelper** розробляється за методологією Scrum з короткими спринтами та практиками DevOps. Система має забезпечувати стабільну роботу протягом навчального року та витримувати пікові сплески звернень (заселення на початку семестру, опалювальний сезон, аварії водопостачання чи електропостачання), а також підтримувати рольовий доступ, сповіщення користувачів і формування звітів.

Синхронна відправка сповіщень (Telegram Bot API / SMTP / Push) або генерація звітів безпосередньо під час HTTP-запиту може спричиняти затримки відповіді API та втрату повідомлень у разі збоїв зовнішніх сервісів. Крім того, потрібна відтворювана контейнеризація, горизонтальне масштабування сервісів та прозорий моніторинг.

## Рішення

Обрати такий технологічний стек та архітектурний підхід:
- **Frontend:** Single-Page Application на **React + TypeScript** (роздається через Nginx у контейнері).
- **Backend API:** **ASP.NET Core (C#)** у форматі модульного моноліту з чітким поділом на доменні модулі, RBAC, валідацією та `Transactional Outbox`.
- **Асинхронний воркер та черга/кеш:** окремий **Background Worker** для обробки подій зміни статусів, відправки сповіщень та генерації звітів у зв'язці з **Redis** (кеш довідників, rate limiting і черга задач).
- **Інфраструктура та DevOps:** упаковка всіх компонентів у Docker-контейнери, розгортання у **Kubernetes** з горизонтальним масштабуванням (HPA) для API та воркера, а також збір метрик і логів через **Prometheus + Grafana + Loki**.

## Наслідки

### Позитивні
- Швидша розробка та реліз фіч у межах спринтів завдяки єдиній кодовій базі модульного моноліту.
- Збої або затримки зовнішніх сервісів сповіщень не блокують створення та оновлення заявок користувачами.
- Підтримка горизонтального масштабування stateless-компонентів у Kubernetes під час пікових навантажень і готова observability-база.

### Негативні / Компроміси
- Вища базова складність інфраструктури на старті (Kubernetes, Redis, окремий воркер і стек моніторингу вимагають більше налаштувань, ніж простий односерверний запуск).
- Потрібно дотримуватися внутрішніх меж модулів у коді, щоб уникнути тісної зв'язності всередині API.
