# ADR-0003: Вибір Alpine-образів, non-root користувачів та ізольованих мереж у Docker Compose

- **Статус:** Прийнято (Accepted)
- **Дата:** 2026-11-25

## Контекст

У Лабораторній роботі №2 архітектура контейнерів системи **DormHelper** переноситься у локальне середовище розробки та тестування за допомогою Docker і Docker Compose. Сервіси обробляють заявки на ремонт гуртожитку, персональні дані мешканців, фотографії та черги задач, тому важливо:
- зменшити розмір образів і поверхню атаки, не тягнучи у фінальні контейнери компілятори чи інструменти збірки;
- не запускати процеси застосунку від імені `root` усередині контейнера;
- не відкривати базу даних `PostgreSQL` назовні хосту та не давати прямого мережевого доступу до БД із `frontend`-контейнера.

## Рішення

1. **Multi-stage builds та легковагові базові образи (`alpine`):** для `frontend` та `backend` застосовується багатоетапна збірка, де етапи компіляції/збірки відокремлені від фінального runtime-образу на базі `alpine`.
2. **Запуск від непривілейованого користувача (`non-root`):** у `backend/Dockerfile` створюється окремий користувач `appuser` (`UID 10001`) з переходом через інструкцію `USER 10001`, а для `frontend` використовується образ `nginxinc/nginx-unprivileged:1.27-alpine` (`UID 101`).
3. **Розділення мереж та `healthcheck`:** у `docker-compose.yml` створюються мережі `frontend-net` та ізольована `backend-net` (`internal: true`). Контейнер `db` підключений лише до `backend-net`, не публікує порт на хост, а запуск `backend` та `frontend` прив'язаний до `condition: service_healthy`.

## Наслідки

### Позитивні
- Менший розмір фінальних образів і швидше завантаження/збірка в локальному середовищі та CI.
- Зниження ризику ескалації привілеїв у разі компрометації контейнера застосунку.
- Мережева ізоляція бази даних і контрольований порядок старту сервісів без гонок ініціалізації.

### Негативні / Компроміси
- Окремі `alpine`-образи можуть потребувати додаткових утиліт під час діагностики (наприклад, `wget`/`curl` для healthcheck або пакети локалізації/залежностей).
- Потрібно стежити за правами доступу (`chown` / `volumes`) для директорій, куди пишуть процеси під `non-root` користувачем.
